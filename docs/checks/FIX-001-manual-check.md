# FIX-001 머성 수동 확인

기준: `docs/plans/FIX-001-update-source.md` v2. 개발 세션은 생성한 exe를 실행하지 않으며, 아래 실행 확인은 머성이 진행한다.

## 배포 전 주의

- 저장소 `hsk260214-maker/poe-delta`가 비공개인 동안 친구 PC는 로그인 없는 자동 업데이트를 받을 수 없다. "새 설치 파일 필요"의 GitHub 페이지도 친구에게는 404로 보일 수 있다. 새 버전은 `PoeDelta-<버전>.zip`을 직접 전달한다.
- 이번 작업에서는 빌드만 하고 태그·커밋·push·GitHub 릴리스를 만들지 않는다. `release.ps1`의 기존 `git add -A`는 미추적 파일까지 릴리스 커밋에 넣으므로, 실제 릴리스를 요청하기 전에 작업 트리와 포함할 파일을 확인해야 한다.
- 처음 설치용 zip에는 `PoeDelta.exe`, `LICENSE`, `LICENSE-awakened-poe-trade.txt`가 함께 있어야 한다. 개발 빌드의 `dist/app-1.1.0.zip`은 업데이트용 코드 묶음이며 exe 설치 zip과 다르다.

## 처음 실행과 원본 보존

1. `dist/PoeDelta.exe`를 실행하고 창 제목이 `POE Delta v1.1.0`으로 시작하는지 확인한다. 상태 표시줄의 프로그램 이름·버전도 같아야 한다.
2. `%APPDATA%\PoeDelta`가 없고 원본 `%APPDATA%\ExileDelta`가 있는 PC에서는 기존 캐릭터·설정·필터 탭이 보이는지 확인한다. 복사 후 원본 폴더와 파일은 그대로 남아야 한다. 이미 `PoeDelta`가 있으면 그 설정을 유지하고 다시 복사하지 않는다.
3. 원본 Exile Delta도 실행해 원래 캐릭터·설정이 그대로 보이는지 확인한다. 원본과 POE Delta를 함께 실행할 수 있어야 하고, POE Delta를 다시 실행하면 POE Delta의 기존 창만 앞으로 나와야 한다.
4. `%LOCALAPPDATA%\PoeDelta`가 커스텀판의 독립 데이터 위치인지 확인한다. 원본 `%LOCALAPPDATA%\ExileDelta`의 받은 앱 코드·업데이트 상태·PoB 엔진은 복사하지 않는다. PoB 엔진은 첫 실행 때 약 370MB를 한 번 다시 받을 수 있다.
5. 원본 설정 복사 실패 안내가 나타난 경우 이번 실행은 임시 설정을 사용한다. 이번에 바꾼 설정은 다음 실행에 남지 않는다. 다음 실행에서 복사를 다시 시도해야 하며, 원본 폴더를 삭제하거나 옮겨 해결하지 않는다. 반복 실패 시 탈출 기능은 이번 범위가 아니다.

## 업데이트 안내

1. 메뉴의 "프로그램 업데이트 확인"을 누른다. 접근 가능한 릴리스가 없으면 `확인할 수 있는 릴리스가 없습니다 (지금 v1.1.0). 저장소가 비공개이거나 아직 릴리스가 없습니다.`가 표시되어야 한다.
2. 접근 가능한 릴리스가 없는 상태에서 시작 시 자동 확인은 안내 창을 띄우지 않아야 한다. "업데이트 내역 보기"는 오류 대신 릴리스가 없다는 안내를 표시해야 한다.
3. 나중에 저장소를 공개하거나 접근 가능한 릴리스를 만든 뒤에는 업데이트·내역·새 설치 파일 링크의 저장소가 `hsk260214-maker/poe-delta`인지 확인한다. 원작자 저장소로 업데이트하면 안 된다.
