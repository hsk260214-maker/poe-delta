# FEAT-008 아이템 종류별 검색 템플릿과 기본 체크

상태: 기획안 v2, 기획 리뷰 2/3 대상(1/3 보완: 규칙 우선순위, 판별 입력, 회귀 기준). 출처: `docs/BACKLOG.md` 1·2·5번 (2026-11-19 머성 요청·결정).

## 1. 목적

거래소 검색 창(`Ctrl+D`)이 열릴 때의 기본 체크를 아이템 종류별 템플릿 한곳에서 정한다. 판별·옵션 매칭·검색 쿼리 로직은 바꾸지 않는다.

## 2. 현재 동작 (코드 근거)

- `app/trade/trade_window.py` `load()`가 기본값을 직접 정한다.
  - 타락 조건 `self.corrupted`: 모든 아이템에서 체크. 라벨은 타락이면 `타락`, 아니면 `타락 아님`.
  - 몬스터 레벨 `self.monster_level`: 지도에서만 보이고 기본 해제.
  - 링크: 5링크 이상일 때 체크. 아이템 레벨: 금지된 서만 체크.
- `app/trade/query.py` `conditions()`·`heist_conditions()`가 옵션 줄의 체크를 정한다.
  - 희귀 아이템의 일반·분열 옵션, 마법 아이템의 일반 옵션은 체크.
  - 강탈 계약: 필요 직업·목표물 가치 체크, 지역 레벨 해제.
  - 강탈 도면: 공개·전체 구역·인챈트 없음 체크, 지역 레벨 해제.

## 3. 템플릿 5개

판별은 `item_info()`가 **이미 지나는 분기에서 이름표만 기록**한다(`TradeItem.template`). 새 품목 허용표나 별도 클래스 판정을 만들지 않는다.

| 템플릿 | 기록 위치 (기존 분기) | 포함 |
|---|---|---|
| 장비 | `cls in GEAR`인 고유 분기(`legacy`)와 `equipment` 분기 | 무기, 방어구, 장신구, 주얼(일반·심연·성단) |
| 지역 레벨 | `cls in heist.CATEGORIES` 분기, 비고유 분기의 `category == "Map"` | 지도(일반·악몽·바알 사원·쉐이퍼 수호자·고유), 강탈 계약·도면 |
| 젬 | 비고유 분기의 `category == "Gem"` | 스킬 젬, 보조 젬 |
| 플라스크 | 비고유 분기의 `category == "Flask"` | 생명력·마나·혼합·유틸리티 플라스크 |
| 기타 | 금지된 서 분기, 살덩이 분기 | 금지된 서, 살덩이 |

- 어느 분기에도 해당하지 않으면 이름표가 비고, 기본값을 바꾸지 않는다.
- `info.supported`, `blocked_reason`, 창 오류(`self._error`)는 그대로 쓴다. 템플릿이 차단을 풀거나 새로 만들지 않으며, 미지원 품목의 기존 사유도 그대로다.

## 4. 기본값 변경 (이번 범위의 동작 변화는 이 두 가지뿐)

적용 순서: 템플릿이 **지역 레벨이면 4.1만** 적용하고, 그 밖의 템플릿에는 4.2만 적용한다. 두 규칙은 한 아이템에 함께 적용되지 않는다.

1. **지역 레벨 템플릿** (BACKLOG 1번): 타락 여부와 관계없이, 기존 코드가 유효하다고 판정해 화면에 노출한 레벨 조건 하나만 체크한다.
   - 지도: `info.monster_level`이 값이 있어 `몬스터 레벨` 체크박스가 보일 때 그것만 체크.
   - 강탈 계약·도면: `heist.area_enabled()`가 열려 `지역 레벨` 줄(`heist_area`)이 있을 때 그것만 체크.
   - 그 밖의 선택 가능한 조건은 모두 해제: 옵션 줄, 필요 직업·목표물 가치·구역 수·인챈트 없음, 타락, 링크, 아이템 레벨, 영향력.
   - 레벨이 없거나 기존 레벨 게이트가 닫혀 있으면 선택된 조건이 0개다. 이는 선택 가능한 조건 기준이며, 고정 필터가 남은 검색 자체는 그대로 가능하다.
   - 지도 정체성 ID, 정확한 베이스·범위 버튼, 지도 등급, 역병 아님, 희귀도 같은 고정 필터는 바꾸지 않는다.
2. **그 밖의 템플릿의 타락** (BACKLOG 2번, 머성 결정 "타락 아이템만 해제"): 아이템이 타락했으면 `타락` 조건을 기본 해제한다. 타락하지 않은 아이템은 지금처럼 `타락 아님`을 체크한다. 원래 숨기거나 제외하던 경우(금지된 서, 살덩이)는 그대로다.

그 밖의 기본값(옵션 줄, 링크, 아이템 레벨, 영향력, 젬 조건 등)은 현재 값을 그대로 쓴다.

## 5. 구조

- `TradeItem.template`: `item_info()`의 기존 분기에서 기록(§3).
- 새 모듈 `app/trade/templates.py`: 템플릿 이름 상수와 `apply_defaults(info, stats, filters)`. 체크 상태만 바꾸고, 판별·차단·매칭·쿼리 형식은 건드리지 않는다.
- `trade_window.load()`는 기존 기본값을 만든 뒤 마지막에 `apply_defaults`를 한 번 호출한다. `conditions()`의 체크 계산은 그대로다.

## 7. 완료 기준

1. 판별: 장비(일반·심연·성단 주얼, 고유 장비 포함), 지도, 강탈 계약·도면, 젬, 플라스크, 금지된 서, 살덩이 fixture가 기대 템플릿으로 기록된다. 미지원·차단 품목은 `supported`, 차단 문구, 창 오류가 ad590d0과 같다.
2. 지역 레벨, 경우별로 고정:
   - 비타락 지도·타락 지도(몬스터 레벨 있음): 몬스터 레벨만 체크, 타락 포함 나머지 해제.
   - 몬스터 레벨이 없는 지도: 선택 0개.
   - 강탈 계약·도면(지역 레벨 있음): 지역 레벨만 체크. 지역 레벨이 없거나 게이트를 닫은 경우: 선택 0개.
3. 그 밖의 템플릿: 타락·비타락 장비, 젬, 플라스크 각각에서 타락이면 `타락` 해제, 비타락이면 `타락 아님` 체크. 금지된 서·살덩이는 타락 조건이 지금처럼 숨겨진다.
4. 사용자가 체크를 바꾸면 그대로 검색에 반영된다(기본값만 바뀜).
5. 회귀: 같은 원문의 기본 검색 payload를 ad590d0과 비교한다. 허용하는 차이는 다음뿐이다.
   - 지역 레벨 템플릿: 선택 가능한 조건(옵션 줄, 강탈 조건, 타락, 링크, 아이템 레벨, 영향력)의 제거와, 현재 형식 그대로의 몬스터·지역 레벨 조건 추가. 지도 정체성 ID, 정확한 베이스·범위, 등급, 역병 아님, 희귀도는 같아야 한다.
   - 그 밖의 템플릿: 타락 아이템의 `corrupted` 필터 제거.
   - 그 외 차이는 실패로 본다.
