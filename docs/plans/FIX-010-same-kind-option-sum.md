# FIX-010 같은 종류의 같은 옵션 합산

상태: 기획안 v3, 기획 리뷰 3/3 대상(2/3 보완: 종류·ID별 허용 목록, 양성·대조 증거, 정수 한정, 전환 확인, 저항 상대 위치). 출처: `docs/BACKLOG.md` 4번, 머성 결정 "같은 종류 안에서만".

## 1. 문제

- 사실: 같은 종류(예: 일반 옵션)에 같은 거래소 옵션이 두 줄 이상 있으면, 지금은 줄마다 따로 조건을 만든다(`app/trade/query.py` `conditions()`). 예: 고급 복사(`Ctrl+Alt+C`)에서 접두어 두 개가 각각 `생명력 최대치 +#`를 주는 경우.
- **가설(미검증)**: 거래소는 한 아이템의 같은 종류·같은 ID 수치를 합계 하나로 평가한다. 그렇다면 줄마다 보낸 같은 ID 조건은 큰 줄 하나의 경계와 같아져 합계보다 낮은 조건이 된다.
- 가설이 확인되기 전에는 합산 검색을 열지 않는다(§4).

## 2. 방안

- 새 모듈 `app/trade/combine.py`. `conditions()` 결과에 한 번 적용하고, 그 뒤에 기존 `resistance_rows()`를 실행한다.
- **첫 범위는 더하기만 하는 양수 수치 옵션**으로 제한한다. 아래를 **모두** 만족하는 줄끼리만 합친다.
  - 같은 종류(`kind`), 같은 단일 거래소 ID(`match.id`), 묶음 조건(`match.ids`)이 아님.
  - `(kind, 전체 ID)`가 검증 허용 목록 `combine.VERIFIED`에 있음(§4).
  - 수치 1개(`match.rolls` 1개)이고 그 값이 양의 정수. 소수는 이번 범위에서 제외.
  - 변환 없음: `invert`, `inverted`, `negate`가 모두 거짓이고, 영문 원문에 `reduced`·`less`가 없음.
  - 고정값(`match.value`)이 없고, 스킬·보조 젬 부여 줄이 아님.
  - 옵션 게이트가 열려 있음(`option_gate()` 결과가 빈 문자열)이고, 기본 체크 상태가 같음.
  - 원소 저항 합산에 쓰이는 줄(`resistance.role()`이 elemental·hybrid·total)이 아님. 그래서 총 원소 저항의 합계와 출처 수치는 합산 전후가 같다.
  - 강탈·젬·살덩이 전용 줄, 고유 아이템의 짝 처리 줄(`detail` 있음), 운명 줄이 아님.
- 종류 전환: 같은 ID라도 `alternate_id`가 같다고 가정하지 않는다. 원본 줄들의 `alternate_id`가 모두 같을 때만 합치고, 다르면 따로 둔다. 전환 대상 `(종류, alternate_id)`가 `VERIFIED`에 없으면 합친 줄의 `종류 전환`을 막는다.
- 합친 줄
  - 위치: 첫 원본 줄 자리. 나머지 원본 줄은 목록에서 빠진다.
  - 값: 원본 수치의 합. 최소값은 현재 규칙 `default_minimum(합계, 비율)`을 그대로 적용한다.
  - 표시: 첫 원본 문구의 수치를 합계로 바꾼 한 줄. 배지는 기존 배지에 `합산`을 덧붙인다(예: `일반 · 합산`).
  - 툴팁: 원본 줄 전체. 새 필드 `StatCondition.sources`를 쓴다. `detail`은 쓰지 않는다(`trade_window.py`가 `detail`이 있으면 최소·최대 입력을 숨기기 때문).
  - 체크와 최소·최대 입력은 다른 줄처럼 편집할 수 있다.
- 종류가 다르면(고정 + 일반, 일반 + 제작 등) 합치지 않는다.

## 3. 범위 밖

- 수치 2개 이상, 음수·감소·반전 옵션, 고정값, 젬 부여 옵션: 지금처럼 따로 둔다.
- 종류를 넘는 합산(총 생명력 같은 합계 조건), 원소 저항 합산(이미 별도 기능).

## 4. 실검증 게이트

- **2026-11-20 머성 결정:** 실검증(원문·카카오 링크)을 건너뛰고 `combine.OPEN_ALL = True`로 조건을 갖춘 모든 `(kind, 전체 ID)`에 합산을 켠다. 아래 절차는 문제가 생겼을 때 개별 확인용으로 남긴다.
- `combine.VERIFIED`: 확인을 마친 `(kind, 전체 ID)` 묶음의 허용 목록. 처음에는 비어 있다. 목록에 없는 줄은 합칠 조건을 갖춰도 지금처럼 따로 보이고 따로 전송된다. 전역 스위치는 두지 않는다.
- 한 ID를 확인해도 그 `(kind, 전체 ID)` 하나만 연다. 다른 ID·종류는 각각 따로 확인한다. 개발과 테스트는 목록을 임시로 채운 상태로 한다.
- 필요 자료: 같은 옵션이 두 줄로 나온 실제 아이템의 고급 복사 원문 1개(머성 제공). 없으면 파생 fixture임을 표시하고, 허용 목록은 비워 둔다.
- 확인 방법(카카오 거래소, 링크 2개, 머성 확인). 대상 `(kind, 전체 ID)` 하나만 조건으로 넣는다.
  1. 합계 조건 링크: 최소값 T를 "개별 줄의 최대값보다 크고 합계 이하"로 정한다. **양성 증거**는 결과 안의 한 매물에서 해당 옵션의 개별 줄이 모두 T 미만이고 합계는 T 이상임을 확인하는 것이다. 거래소 화면에서 개별 줄을 구분할 수 없으면 이 증거를 얻을 수 없으므로 미확인으로 둔다.
  2. 대조 링크: 최소값 = 그 매물의 합계 + 1(정수의 다음 값). 1번의 **같은 매물이 결과에서 빠지는지** 확인한다.
  - 두 조건이 모두 확인돼야 그 `(kind, 전체 ID)`를 `VERIFIED`에 넣는다.
- 일반 복사(`Ctrl+C`)에서도 같은 옵션이 여러 줄로 나오는지는 같은 아이템의 일반 복사로 함께 확인한다.
- 두 링크가 기대대로 나오기 전에는 허용 목록에 넣지 않는다. 이번 기획 승인은 실제 요청 허가가 아니다.

## 5. 완료 기준

1. 허용 목록에 든 `(kind, 전체 ID)`: 같은 종류·같은 ID의 양의 정수 수치 1개 옵션 두 줄이 첫 원본 자리의 한 줄이 되고, 최소값은 `default_minimum(합계, 비율)`과 정확히 같으며, 검색 조건은 하나다.
2. 허용 목록에 없는 ID·종류는 조건을 갖춰도 따로 남는다(목록에 다른 ID만 있는 경우 포함).
3. 표시: 배지가 `기존 배지 · 합산`, 툴팁이 원본 줄 전체, 체크와 최소·최대 입력이 편집되고 편집 값이 검색에 반영된다.
4. 전환: 원본 줄의 `alternate_id`가 다르면 합치지 않는다. 전환 대상이 허용 목록에 있으면 합친 줄 전체가 전환되고, 없으면 `종류 전환`이 막힌다.
5. 합치지 않는 경우를 각각 고정: 종류가 다름, 묶음 ID, 수치 2개 이상, 소수, 음수·감소·반전, 고정값, 젬 부여, 옵션 게이트 닫힘, 기본 체크 상태가 다름, 원소 저항 줄, 강탈·젬·살덩이·고유 짝·운명 줄.
6. 원소 저항: 총 원소 저항 줄의 값과, 그 줄이 기준으로 삼는 첫 저항 원본 줄 대비 상대 위치가 합산 전후 같다(앞쪽 병합으로 절대 순번이 바뀌어도 됨).
7. 허용 목록이 빈 상태, 그리고 합칠 줄이 없는 기존 fixture·감사 원문의 검색 payload는 ad590d0과 바이트 단위로 같다.
