# FIX-009 공격·주문 피해 막기 확률 검색 (한국어 문구로 구분)

상태: 기획안 v2, 기획 리뷰 2/3 대상(1/3 보완: 링크별 전체 ID·옵션 종류, 종류 전환 우회 차단). 선행: FEAT-005 v3(K·E 판정표). APT 고정 커밋 `803d188d1359c4d5b1e3826da5dc680ea74a158f`.

## 1. 문제

- 방패 옵션 전수 점검(160종류) 결과 `#%의 확률로 주문 피해를 막아냄`(일반·제작)이 `한국어·번역 연결 불일치`로 회색이다(scratch `shield-option-audit.csv`). 같은 원인으로 일반 `공격 피해 막기 확률 +#%`도 회색이다(FEAT-005 v3에서 역방향 포함을 넣지 않아 회색으로 남긴 항목).

## 2. 근거 (고정 APT)

- `en/stats.ndjson` L214·L215는 각각 `trivial-merge` 묶음이며, 두 항목의 영문 매처가 같다.
  - L214: `#% Chance to Block Attack Damage`(`stat_2530372417`)와 `+#% Chance to Block Attack Damage`(`stat_1702195217`) 모두 매처 `#% Chance to Block Attack Damage`.
  - L215: `#% Chance to Block Spell Damage`(`stat_561307714`)와 `+#% Chance to Block Spell Damage`(`stat_19803471`) 모두 매처 `#% Chance to Block Spell Damage`.
- `ko/stats.ndjson`의 같은 묶음은 두 항목이 **서로 다른 한국어 매처**를 가진다.
  - `#%의 확률로 공격 피해를 막아냄` → `stat_2530372417`, `공격 피해 막기 확률 #%` → `stat_1702195217`
  - `#%의 확률로 주문 피해를 막아냄` → `stat_561307714`, `주문 피해 막기 확률 #%` → `stat_19803471`
- 그래서 E(번역)는 두 ID를 `count`로 묶고, K(한국어)는 문구에 맞는 ID 하나를 고른다. K의 ID는 E 묶음의 원소다.

## 3. 방안

- §5.2 판정표에 좁은 행 하나를 더한다. 다음을 **모두** 만족할 때만 K 단일을 쓴다.
  - K가 정확한 한국어 매처(표의 네 문구 중 하나)로 확정한 `ref`와 전체 ID 하나.
  - E가 고정 묶음(L214 또는 L215)의 두 전체 ID로 확정한 `count`이며, K의 전체 ID가 그 두 전체 ID 중 하나.
  - K와 E의 옵션 종류(explicit 등), 부호, 고정값, 캡처 값이 같다.
  - K의 전체 ID가 **확인된 전체 ID 목록**(§4)에 있다.
- 확인되지 않은 전체 ID는 회색이다. 이때 E의 `count`로 대신 보내지 않는다.
- 적용 대상은 위 두 묶음뿐이다. 다른 묶음, 다른 ID, 수치·변환이 다른 행, 모호한 결과는 지금처럼 회색이다. 일반 부분집합 예외로 넓히지 않는다.
- 결과는 일반 `and` 필터 하나다(묶음 `count`가 아님). 기본 체크·최소값 규칙은 다른 일반 옵션과 같다.
- 기존 R2 묶음 경로(K와 E가 같은 묶음일 때)와 영문 원문 검색 경로는 바꾸지 않는다.
- **일반↔분열 종류 전환(`alternate_id`)**: 이 예외로 열린 행에서 종류를 전환하면 전환된 전체 ID(예: `fractured.stat_561307714`)가 확인 목록에 없으므로 회색이 되고 payload에서 빠진다. 공용 쿼리 경로에서도 확인 목록 밖 전체 ID를 보내지 않는다.

## 4. 게이트와 요청 예산

- 앱이 만든 그대로의 카카오 링크 2개를 머성이 확인한 뒤 연다. 그 전에는 지금처럼 회색이다.
  1. 링크 1: 전체 ID **`explicit.stat_561307714`**, 옵션 종류 일반(explicit). 대상 원문: 희귀 방패에 일반 옵션 `15%의 확률로 주문 피해를 막아냄`(감사 문구로 만든 고정 자료, 파생임을 표시). 판정: 결과 방패가 모두 같은 문구의 일반 옵션을 가진다.
  2. 링크 2: 전체 ID **`explicit.stat_1702195217`**, 옵션 종류 일반(explicit). 대상 원문: 이 옵션이 붙는 방패가 아닌 부위 하나(개발이 감사 자료에서 고름)에 일반 옵션 `공격 피해 막기 확률 +20%`. 판정: 결과가 모두 같은 문구의 일반 옵션을 가진다.
- 확인된 전체 ID 목록은 위 두 개뿐이다. 같은 번호의 다른 종류(`crafted.`·`implicit.`·`fractured.`)와 나머지 두 번호(`stat_2530372417`, `stat_19803471`)의 모든 종류는 회색이다. 따라서 **제작 옵션 방패의 주문 막기(`crafted.stat_561307714`)는 이번에도 회색**이며, 열려면 별도 허가와 확인이 필요하다. 결과 0건·판별 불가는 미확인이다. 요청 예산은 2개다.

## 5. 완료 기준

1. 링크 1 대상 원문의 일반 옵션 `#%의 확률로 주문 피해를 막아냄`이 게이트 후 `explicit.stat_561307714` 단일 `and` 필터로 한 번 전송된다.
2. 링크 2 대상 원문의 일반 옵션 `공격 피해 막기 확률 +#%`가 게이트 후 `explicit.stat_1702195217` 단일 `and` 필터로 전송된다.
3. 회색 회귀: 게이트 전 두 행, 제작 `crafted.stat_561307714`, 같은 번호의 implicit·fractured, 나머지 두 번호의 모든 종류, 다른 묶음, 종류·수치가 다른 행, 그리고 열린 행을 분열로 전환한 경우(`fractured.…`가 전송되지 않음). 미확인 ID에서 E `count`로 대체 전송하지 않는 테스트.
4. R2 묶음 경로와 영문 원문 검색의 payload는 지금과 같다.
5. 감사 전체·저장 원문 payload는 위 두 옵션 행의 변화 외에 지금과 바이트 단위로 같다.
