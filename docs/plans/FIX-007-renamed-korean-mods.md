# FIX-007 이름이 바뀐 한글 옵션 문구 대응표 (첫 항목: 허상)

상태: 기획안 v2, 기획 리뷰 2/3 대상(1/3 보완: 검증된 종류·ID 명시). 선행: FEAT-005(K·E 두 경로 판정). APT 고정 커밋 `803d188d1359c4d5b1e3826da5dc680ea74a158f`.

## 1. 문제

- 머성 원문(희귀 악몽 지도 `야만적인 결의`)의 `{ 희귀만 }` 아래 `지역에 허상 등장`이 회색이다(`거래소 옵션과 맞추지 못함`).
- 원인: APT 한국어 데이터는 같은 옵션을 예전 이름 `지역에 신기루 등장`으로 갖고 있다(`ref` `Area contains a Mirage`, `explicit.stat_2436559047`). 3.30 한글 클라이언트는 `지역에 허상 등장`으로 표시한다. 한→영 번역 사전에도 새 이름이 없다. 같은 원문의 `지역에 환영의 거울 1개 등장`(`Area contains a Mirror of Delirium`)은 이름이 그대로라 정상이다.

## 2. 근거

- 머성 확인(2026-11-19): `악몽 지도` + `explicit.stat_2436559047` 카카오 링크에서 나온 지도에 `지역에 허상 등장`이 붙어 있음을 확인했다.

## 3. 방안

- 데이터 파일(예: `data/ko_aliases.json`)에 **확인된 항목만** 둔다. 항목 형식: 현재 게임 한글 문구(정확한 문장) → APT 한국어 매처 원문(옛 이름), 영문 `ref`, **검증된 옵션 종류**, **검증된 전체 거래소 ID**, 확인 날짜·방법.
  - 첫 항목: `지역에 허상 등장` → `지역에 신기루 등장` / `Area contains a Mirage` / 종류 `explicit` / ID `explicit.stat_2436559047` / 2026-11-19 머성 카카오 링크(악몽 지도 + 이 ID)에서 확인.
  - 같은 `ref`가 고정 APT 자료에서 `enchant.stat_2436559047`도 갖지만, 카카오 확인은 explicit 링크였으므로 enchant는 대응표 범위에 넣지 않는다.
- 범위: 첫 항목은 **수치가 없는 정확한 문장**만 맞춘다. 수치가 있는 별칭은 별도 검증 전까지 일반화하지 않는다.
- 판정 순서: FEAT-005 판정표가 먼저다.
  - K 경로: 줄이 대응표 키와 정확히 같을 때만 APT 한국어 매처 원문으로 바꿔 평소대로 해석한다.
  - E 경로: **기존 번역이 없을 때만** 대응표의 영문 `ref` 문구로 해석한다. 기존 번역이 있으면 그 결과를 그대로 쓰며, 기존 번역의 충돌·모호함을 대응표로 덮지 않는다.
- 결과 검사: 판정표를 거친 최종 결과의 종류·전체 ID·`ref`가 대응표에 기록된 값과 모두 같아야 한다. 같은 문구라도 종류(예: enchant)·ID·`ref` 중 하나라도 다르면 **회색, payload 제외**.
- 이름이 비슷하다는 추측으로 항목을 늘리지 않는다. 새 항목은 실제 원문 + 카카오 링크 확인 후 추가한다.

## 4. 완료 기준

1. 머성 원문(희귀 악몽 지도 `야만적인 결의`)에서 `지역에 허상 등장` 줄이 `explicit.stat_2436559047`로 **한 번만** 전송되고, 희귀 지도 일반 옵션의 기본 체크 규칙대로 동작한다. 같은 원문의 `지역에 환영의 거울 1개 등장` 줄과 지도 정체성 조건(정확 베이스, 역병 아님, 희귀도)은 지금과 같다.
2. 대응표에 없는 문구와 다른 모든 옵션의 payload는 FEAT-005/006과 바이트 단위로 같다.
3. 같은 `ref`의 enchant 줄(`지역에 허상 등장 (enchant)`)은 대응표로 열리지 않고 회색인 회귀 테스트.
4. 대응표 항목의 최종 종류·ID·`ref`가 기록값과 다르면 회색이 되는 테스트, 그리고 기존 번역이 있는 줄에서는 대응표가 E 결과를 바꾸지 않는 테스트.

## 5. 범위 밖

- 다른 이름 변경 후보의 일괄 탐색, APT 데이터 갱신.
