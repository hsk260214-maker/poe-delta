## 1. 목표

카카오 PoE1 PC 3.30 마녀단(Covens) 리그의 가판대(상인의 탭, 즉시 구입)에 실제 매물이 올라오는 품목을 조사해 POE Delta에 내장한다.

- 파우스투스 화폐 교환소에서 거래되는 품목은 제외한다.
- 기존 검색 카테고리(장비·지도·젬·플라스크 등)가 있는 품목은 기존 검색과 차단을 그대로 둔다.
- 카테고리가 없는 품목에만 `웹 거래소 확인 요망` 안내와 카카오 웹 검색 버튼을 붙인다. 버튼은 사용자가 누를 때만 정확한 품목명과 `securable` 조건으로 카카오 웹 거래소를 연다. 앱 내 시세 조회나 자동 열기는 없다.
- 실매물 확인 기준: 카카오 마녀단 `즉시 구입` 검색에서 정확한 품목의 매물 행과 `은신처로 이동` 버튼이 하나라도 보이면 확인. 관측 시각과 세부 패치 번호는 필수가 아니다(세부 패치는 `미확인`으로 기록).

## 4. 앱 반영 상태

| 단계 | 내용 | 리뷰 |
|---|---|---|
| 초대 4종 | 로컬 시범 파일에 등록, 수동 웹 버튼 동작 | 개발 리뷰 승인 |
| 강탈 장비 36종 추가 (총 40종) | 번들 수정 없이 로컬 시범 파일에만 등록. 해시 `664a9766…` | 개발 리뷰 1/3 승인 |

- 실매물 목록은 Git 제외 로컬 파일 `tools/.cache/kakao_observed_pilot.json`에만 있고, 환경 변수 `POE_DELTA_LOCAL_KAKAO_PILOT`로 지정한 로컬 앱에서만 열린다. 공개 배포본에서는 0개(닫힘).
- `data/trade_items.json`(번들)은 수정하지 않는다. 한때 시신 데이터를 번들에 직접 추가했다가 개발 리뷰에서 반려되어 원복했다.
- 카카오 웹 거래소 원본 자료의 재배포 허용 여부는 확인되지 않았다. 공개 배포 전에 별도 확인이 필요하다.

## 5. 진행 중 작업의 알려진 문제 (시신 144종 단계)

현재 작업 트리 상태로는 완료가 아니다.

- `app/trade/web_fallback.py`가 번들에 없는 품목도 로컬 시범 파일에 있으면 열리도록 수정되었고, 해시가 `8d901be8…`로 바뀌었다. 리뷰를 받지 않았다.
- 시신 104종 목록에 시신이 아닌 항목이 섞여 있다: 관로(강탈 장비인데 `Corpse`로 중복 분류), 저주받은 귀염둥이(교환소 품목), 바알 위상 및 바알 위상 고유 4종(야심·아름다움·협력·호기심). 정리 후 실제 시신 수를 다시 세야 한다.
- 이 때문에 `tests/trade/test_web_fallback.py`의 등록 품목 전체 검사 1건이 `관로`에서 실패한다.
- 강탈 장비는 36종으로 등록했지만 관로를 포함하면 37종이다. 관로를 강탈 장비 쪽에 정식 포함할지 결정이 필요하다.

## 6. 남은 일

1. 시신 목록에서 비시신 항목을 걸러 내고 관로를 강탈 장비로 정리한다. 해시를 다시 맞추고 테스트를 통과시킨 뒤 개발 리뷰를 받는다.
2. 나머지 미분류 후보(부적·수호·용병 소환장 등 기타 특수 품목)의 실매물을 확인한다.
3. 공개 배포 여부는 자료 재배포 허용 확인 후 별도로 결정한다. 커밋·배포는 요청 범위에서만 진행한다.

## 7. 협업 프로세스에서 있었던 문제

- 리뷰 결과가 기획 채널로 자동 반환되지 않아 흐름이 끊긴 적이 있다. 이후 모든 요청에 기획 채널 직접 회신을 명시하고 `AGENTS.md`에 지침으로 남겼다.
- 기획 채널이 구현까지 직접 수행한 구간이 있다(역병 지도, 감사 패키징, 강탈·시신 등록). 지침상 구현은 개발 채널 담당이다.
